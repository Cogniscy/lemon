\section{Related Work}
\subsection{RDF-to-text benchmarks and standard metrics}
The WebNLG Challenge introduced RDF-to-text generation as a benchmark task: systems receive DBpedia-derived RDF triples and generate fluent verbalizations \cite{gardent2017webnlg}. Later WebNLG+ tasks extended the setting to bilingual and bidirectional generation \cite{castroferreira2020webnlg}. The standard automatic evaluation stack includes n-gram and edit-distance metrics as well as neural reference metrics. BLEU remains a conventional reference point \cite{papineni2002bleu}, while BERTScore \cite{zhang2020bertscore} and BLEURT \cite{sellam2020bleurt} add contextual or learned similarity. These metrics compare generated text with reference text and therefore remain mostly holistic.

\subsection{Data coverage and faithfulness metrics}
A second line of work evaluates generated text against the source data. Wiseman et al. proposed information-extraction-based evaluation for data-to-document generation \cite{wiseman2017challenges}. PARENT aligns entailed n-grams with semi-structured source tables and references \cite{dhingra2019parent}. Data-QuestEval uses question generation and answering for reference-less data-to-text evaluation \cite{rebuffel2021dataquesteval}. AlignScore learns a unified alignment function for factual consistency \cite{zha2023alignscore}. The nearest graph-to-text predecessor is FactSpotter, which decides whether a given triple is present in the generated text and reports strong correlation with human annotations for correctness, coverage, and relevance \cite{zhang2023factspotter}. \lemonscore{} complements FactSpotter by moving from binary triple-level decisions to weighted factor-level decisions inside a predicate.

\subsection{Atomic fact and semantic graph evaluation}
Atomic factuality metrics such as FActScore decompose generated text into atomic claims and verify each claim against a knowledge source \cite{min2023factscore}. VERISCORE extends this line to verifiable claims in long-form generation \cite{sun2024veriscore}. These methods are text-directed: the decomposition target is the generated text. \lemonscore{} is source-directed: the decomposition target is the graph predicate.

Semantic graph evaluation metrics such as Smatch compare semantic graphs, especially AMR graphs, by maximizing triple overlap under variable alignment \cite{cai2013smatch}. S$^2$match and Smatch++ add softer and more standardized variants of graph matching \cite{opitz2020s2match,opitz2023smatchpp}. These metrics are important for parser evaluation, but they require a semantic graph representation of the generated text. \lemonscore{} avoids inverse parsing in the first baseline and instead checks factor evidence directly in the text.

\subsection{Predicate decomposition and synthetic adjudication}
The theoretical motivation for factor decomposition comes from predicate-argument and frame-based semantics. FrameNet represents lexical meanings through frames and frame elements \cite{baker1998framenet}; PropBank annotates predicate-argument structures over corpora \cite{palmer2005propbank}; VerbNet provides broad-coverage verb classes with semantic roles \cite{schuler2005verbnet}. These resources support the view that predicate meaning can be represented through typed roles rather than through a single label.

The present pilot uses LLM-generated and LLM-adjudicated predicate decompositions as a bootstrap. This is not equivalent to expert annotation. Prior work on LLM-as-a-judge documents useful agreement with human preferences as well as position, verbosity, and self-enhancement biases \cite{zheng2023mtbench}. Surveys and empirical studies argue that LLM judges must be calibrated against human judgments before being treated as primary evaluators \cite{gu2024llmjudge,gilardi2024llmjudges}. We therefore mark our adjudicated resource as synthetic.
