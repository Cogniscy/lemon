\section{Related Work}
\subsection{RDF-to-text benchmarks and reference metrics}
The WebNLG Challenge established RDF-to-text generation as a benchmark task in which systems map DBpedia-derived RDF triples to natural language \cite{gardent2017webnlg}. The WebNLG+ shared task extended the setting to bilingual and bidirectional generation and included both automatic and human evaluation \cite{castroferreira2020webnlg}. The GEM benchmark further argued for broader evaluation practice and challenge sets for NLG evaluation \cite{gehrmann2021gem}. The standard WebNLG automatic stack includes reference-based metrics such as BLEU, METEOR, chrF++, TER, BERTScore, and BLEURT \cite{papineni2002bleu,zhang2020bertscore,sellam2020bleurt}. These metrics produce useful holistic similarity signals, but they do not localize errors to a source predicate or to a semantic role inside the predicate.

\subsection{Source-aware coverage and factuality metrics}
A second line of work evaluates generated text against input data. PARENT weights n-gram precision and recall by evidence in the source table and reference text \cite{dhingra2019parent}. Data-QuestEval adapts question-answering evaluation to data-to-text semantic coverage without requiring a reference \cite{rebuffel2021dataquesteval}. AlignScore learns a unified alignment function for factual consistency across several supervision sources \cite{zha2023alignscore}. The closest graph-to-text predecessor is FactSpotter, which decides whether a given triple \((s,p,o)\) is present in a generated text and reports strong correlations with human judgments for data correctness, coverage, and relevance \cite{zhang2023factspotter}. \lemonscore{} complements this line by moving from a binary whole-triple decision to a weighted decomposition of the predicate into semantic factors.

\subsection{Atomic facts, semantic graphs, and directionality}
Atomic factuality metrics decompose generated text into verifiable claims. FActScore evaluates long-form text by decomposing it into atomic facts and checking support against a knowledge source \cite{min2023factscore}; VERISCORE extends claim verification for long-form factuality \cite{sun2024veriscore}. This direction is text-driven: the output text is decomposed into claims. \lemonscore{} is source-driven: the source predicate is decomposed into factors that can be checked in text or in a reconstructed graph.

Semantic graph metrics such as Smatch compare graph structures, especially AMR graphs, by maximizing overlap under node alignment \cite{cai2013smatch}. S$^2$match and Smatch++ add softer or more standardized graph comparison variants \cite{opitz2020s2match,opitz2023smatchpp}. These metrics are important for parser evaluation, but they presuppose graph representations on both sides. \lemonscore{} instead evaluates factor evidence from graph--text pairs and only uses reconstructed graphs in the reverse experiment.

\subsection{Text-to-KG extraction and MINE}
Recent text-to-KG work has renewed interest in evaluating whether extracted graphs retain useful information from plain text. KGGen introduces a language-model-based text-to-KG generator and releases MINE, Measure of Information in Nodes and Edges, as a benchmark for testing whether an extractor produces useful KGs from text \cite{mo2025kggen}. Our \minebase{} baseline is inspired by this node/edge information split. It is not a reproduction of the KGGen benchmark, which targets KG extractors on plain text; rather, it adapts the idea to WebNLG graph--text pairs so that Text$\rightarrow$KG recoverability can be compared with Reverse \lemonscore{}.

\subsection{Behavioral testing and metric calibration}
Evaluation metrics should be tested not only by correlation with human judgments, but also by whether they respond correctly to controlled changes. CheckList introduced behavioral tests for NLP models, including invariance tests, where label-preserving perturbations should not change predictions, and directional expectation tests, where perturbations should change predictions in a prescribed direction \cite{ribeiro2020checklist}. Perturbation CheckLists for NLG metrics apply the same idea to automatic metric evaluation \cite{sai2021perturbation}. He et al. use synthetic stress tests to expose blind spots of model-based NLG metrics \cite{he2023blindspots}. Our calibration follows this methodology: relation deletion is a directional test, while entity aliasing and predicate paraphrase templates are invariance-style checks whose quality is explicitly marked.
